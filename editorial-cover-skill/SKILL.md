# Editorial Cover — 简洁的中文内容封面

目标：让封面看上去像专业杂志的编辑设计，而不是通用文生图、营销海报或标题党。
默认无需多轮提问；用户未指定时按下方配置自动选择。以事实准确性优先于吸引眼球。

## 任务工作流（必须逐步执行）

### 1. 读完整内容，不只看标题

输入可以是用户粘贴的全文、Markdown/文本路径、视频脚本或明确的主题。
文章过长时先理解观点与例证，再选图，不得截取前三段后盲目推断。
在工作目录 `outputs/<slug>/` 写 `brief.md`，包含：
- 主题（一句话，非标题复述）
- 核心主张/叙事张力（一句话）
- 能在正文找到支持的具体物体/场景（最多 3 个）
- 禁止误导的细节（如真实人物肖像、尚未发布的产品外观、数据图表或官方 Logo）
- 主要受众及封面的情绪基调

### 2. 将主题映射为「1 个可见对象 + 1 个视觉动作」

优先级：
1. 文章中真实出现的物体/界面/照片（需有授权或用户自有素材）
2. 真实素材的局部、轮廓、剪影、对比或裁切
3. 可以被读者一眼理解的简单视觉隐喻
4. 纯文字和抽象平面布局（无适合可信实物时，优于乱造场景）

默想三种构图方案，按 **内容关联 40% + 一眼可读 25% + 克制感 25% + 素材可信度 10%** 选择最好的一个。不必向用户展示所有候选方案，除非用户要求。

禁止凭空使用悬浮立方体、机器人脑袋、电路发光网络、透明玻璃球、蓝紫色光束来概括所有 AI/科技话题。使用这些元素只有在它们确实是正文所讨论的对象时才允许。

### 3. 平台与字数策略

阅读 `references/platforms.md`。
- 微信公众号：默认 `900×383`（约 2.35:1）、**无标题**、画面主体集中居中方形，额外输出 1:1 裁切预览。没有指定时默认不加频道名/品牌 Logo。
- 小红书：默认 `1080×1440`（3:4），主标题中文 5–12 字，优先不超过两行；最多一个短说明；画面要能在缩略图中识别，注意正方形预览。
- 抖音：默认 `1080×1920`（9:16），主标题中文 4–10 字；核心元素避开上下界面遮挡，留出安全边距。抖音视频投稿形式可能有其他封面裁切，需按实际界面预览。
- 多平台：保留**同一主题与视觉元素**，**分别构图**；禁止简单拉伸原图。
- 用户显式指定文字、平台或尺寸时，覆盖对应默认值，不要强行换成营销标题。

### 4. 美术风格：quiet-editorial（默认）

- 颜色：黑、暖白、灰为主；若有品牌或文章语境需要，允许 **1 个低饱和强调色**。
- 视觉：单一焦点、明显留白、真实质感、自然光线、不过分对称；可用真实局部摄影、克制的杂志风平面、简单线条/图形。
- 构图：主体通常占 25%–55%，其余为留白；不是硬规则，清晰优先。
- 文字：由后处理的 Pillow 排版，**生图阶段不让图像模型渲染中文文字**；避免文字拼写、字距、字体错误。
- 避免：胶质 3D、高亮反射、假景深、过度锐化、光晕、霓虹、浮空 UI、无关装饰、随机小字、带假的 UI 数据、未经验证的品牌/产品外观。
- 可参考用户提供的封面，但不得复刻他人受版权保护的独特构图或商业设计。

### 5. 素材优先级和生图步骤

优先使用用户提供或已有合法授权的原始照片/截图；其次是明确授权、注明来源的素材；再使用当前 agent 中**真实可用**的图像生成工具生成无字底图。
不得虚构已执行的工具，不得虚构素材版权。遇到时效新闻、具体人物、真实产品的未证实外观时，选择示意/抽象表达，避免把合成图冒充现场照。

如果有可用图像生成能力：
1. 写 `outputs/<slug>/prompts/background.md`，明确唯一主题对象、动作、材质、光线、构图、焦点位置与留白、比例，禁止字/水印/Logo（用户提供官方 Logo 且允许使用除外）。
2. 先生成无字原始背景。为不同平台可生成各自画幅版本。保存 `background-wechat.png` 等。
3. 禁止声称生成成功但没有保存文件；缺少可用生图工具时改为纯排版或使用用户素材，并告知限制。

无字生图提示词模板见 `references/prompts.md`。

### 6. 用可复现脚本完成中文排版与输出

安装 Python 3 和 Pillow。macOS 推荐使用虚拟环境：`python3 -m venv ~/.venvs/editorial-cover && ~/.venvs/editorial-cover/bin/pip install Pillow`。
根据 `examples/cover.example.json` 写 `outputs/<slug>/cover.json`，指定原图路径或纯色背景、标题、调色板和平台。
执行：

```bash
~/.venvs/editorial-cover/bin/python scripts/render_cover.py --spec outputs/<slug>/cover.json --out outputs/<slug>/final
```

运行时必须使用实际已安装 Pillow 的 Python。若 Agent 环境自带 Pillow，可以直接用 `python3`。如果使用本 Skill 的绝对路径，脚本位置以实际安装路径为准。脚本负责尺寸、背景裁切、精确中文排字、安全区预览、方形预览；图片生成由 agent 可用工具负责，脚本不假装能调用图片模型。

### 7. 出图检查（必须）

- 文章的核心主题能否通过图像主体解释？解释不清则重选素材。
- 去掉文字后，画面是否仍是可辨认的主题对象？
- 公众号居中方形裁切后，核心对象是否仍可见？
- 小红书/抖音首屏是否易读？文字是否溢出、被遮挡、需要缩小到不可读？
- 有没有 AI 常见塑料质感、违背现实的形体细节、编造 UI/品牌？
- 字体、颜色和层次是否统一？至少保留明显留白，除非文章确实需要信息密度。
- 画幅比例正确，人物/重要物体没有被不合理裁切。
- 使用外部照片/素材时保留来源/授权说明。

不合格时调整 prompt 或构图并重新输出；不要用后期涂抹掩盖生成失败的文字。

### 8. 完成时交付

回报：选用的视觉概念一句话、各平台输出路径、使用了哪类素材（原创/用户提供/已授权/AI 背景/纯排版），以及是否有未处理的限制。不要夸大真实度和版权状态。

## 首次调用示例

用户：`给这篇文章生成公众号和小红书封面，尽量简洁，像编辑设计，不要科技感光效：posts/my-article.md`

执行：读文章 → brief.md → 选一个主体 → 有授权图优先 → 如需生成先生成无字底图 → `cover.json` → `render_cover.py` → 检查预览 → 交付 PNG。
