# 平台规格（默认工作值，非所有入口的官方强制规格）

| 平台 | 默认产物 | 画幅 | 标题默认 | 核心注意 |
|---|---:|---:|---|---|
| 微信公众号首条 | 900×383 | ~2.35:1 | 优先有辨识度的无标题画面；必要时用 6–14 字短标题 | 中央 383×383 可用作方形裁切预览；重要主体与关键词保持在中心 |
| 小红书图文首图 | 1080×1440 | 3:4 | 5–12 中文字符 | 尽量两行内、远离四边、生成中央方形预览 |
| 抖音竖版视频封面 | 1080×1920 | 9:16 | 4–10 中文字符 | 重要内容主要放中部，避免平台 UI 遮盖 |

以上为常见设计用尺寸，而非证明抖音/小红书所有发布入口的唯一有效画幅。

## 关键设计约束

- 微信大图会在部分入口出现不同大小/比例的裁切，不应假设每个入口都采用同一个 1:1 裁切窗口。`preview-wechat-square.png` 仅用于检视中心区。
- 任何平台都要额外在约 375px 屏幕宽度下检查：文章专属词、对象和冲突是否可见；不能只在原尺寸上评审。
- 小红书个人主页等位置可能有缩略图裁切，优先保证主要对象和主题文案落在画面的中间区域。
- 抖音按钮、标题、底部交互区会随客户端版本、设备与发布类型发生变化。以真实客户端预览为最终准则。
- 多平台保持风格不等于只缩放一张图片；可为不同平台提供不同背景文件和标题。

## 内容类型映射

| 内容 | 首选对象 | 应避免 |
|---|---|---|
| AI 模型实测 | 真实硬件、运算产出、实验物件 | 万用机器人头像、全息脑袋 |
| iOS / 软件更新 | 真实设备局部、界面截图、抽象系统形态 | 未经证实的设备、伪造系统截图 |
| 商业/监管新闻 | 真实文件局部、符号化物件、排版 | 假新闻现场、假的官方公章 |
| 观点/评论 | 一个强隐喻、真实日常场景 | 毫无关联的未来城市 |
| 教程/工具测评 | 实物、真实 UI 局部、手部操作 | 一整页细小截图、过多 feature 气泡 |
